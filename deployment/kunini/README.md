# Развёртывание Jellyfin на Kunini

Jellyfin `v12.4` работает в контейнере с закреплённым digest и слушает только `127.0.0.1:8096`. Nginx публикует два HTTPS-входа с WebSocket и длинными медиапотоками:

- `https://media.kunini.ru` — веб-интерфейс с обязательной проверкой через `auth.kunini.ru` и бесшовным SSO;
- `https://media-app.kunini.ru` — стандартный вход Jellyfin для iOS, Android, Android TV, tvOS и других клиентов.

Плагин `Kunini Auth Bridge` убирает второй экран входа в веб-плеере. Проверенные Nginx заголовки `X-Kunini-Auth-*` преобразуются в отдельную Jellyfin-сессию `kunini-<username>-<stable-id>`. Смена пользователя Kunini приводит к смене Jellyfin-сессии до показа интерфейса. Новый пользователь `dkunin` получает права администратора по явному allowlist; остальные новые пользователи получают обычные права просмотра. Исходная локальная учётная запись `dkunin` и её пароль сохраняются для аварийного и клиентского входа.

Плагин `Kunini Discover` добавляет после локальной полки `More Like This` веб-полку `Discover beyond your library`, а на странице поиска — полку `Not in your library` с внешними совпадениями по введённому названию. Кнопка `NEXT` в заголовке рекомендаций загружает следующую страницу TMDb без ухода с карточки Jellyfin. На странице персоны появляется внешняя фильмография: для актёра — фильмы с его участием, для режиссёра — поставленные им фильмы; уже имеющиеся в медиатеке позиции исключаются. Плагин получает рекомендации, результаты поиска и фильмографию из бесплатного API TMDb. Карточка помечена `NOT IN LIBRARY`, содержит кнопку `MAGNET`, а `View details` открывает внутри Jellyfin полноценную страницу внешнего фильма или сериала с постером, фоном, синопсисом, рейтингом, жанрами, возрастным рейтингом и датой выпуска. На этой странице `MAGNET` занимает место локальной кнопки воспроизведения, а при наличии трейлера рядом появляется `TRAILER`: видео загружается только после нажатия в privacy-enhanced YouTube-модальном окне без автозапуска, с резервной ссылкой `Open on YouTube`. Обе кнопки `MAGNET` открывают новую вкладку `https://magnet.kunini.ru/?query=<название>%20<год>`, где название и год берутся из метаданных рекомендации и кодируются как параметры URL.

Интеграция интерфейса ограничена Jellyfin Web на `media.kunini.ru`: нативные мобильные и ТВ-клиенты продолжают работать без этой полки. TMDb-запросы кэшируются на 30 минут; собственный бесплатный ключ можно передать через `KUNINI_DISCOVER_TMDB_API_KEY`, иначе используется публичный ключ встроенного TMDb-провайдера Jellyfin. Постеры возвращаются через валидируемый same-origin endpoint плагина; сервер получает их через бесплатный image cache `i0.wp.com`, поскольку прямой TMDb CDN блокируется в части клиентов. Это приложение использует TMDB API, но не одобрено и не сертифицировано TMDB.

Локальный интерактивный макет запускается командой `./preview-discover.sh`; после запуска откройте напечатанный адрес. Макет использует те же JavaScript и CSS, что и плагин, а данные рекомендаций фиксированы для безопасной проверки без Jellyfin-сервера.

Direct-вход разрешается bridge только для точного host `media-app.kunini.ru` от доверенного Docker gateway `172.30.0.1` либо с proxy-маркером, который app-vhost принудительно перезаписывает точным host. Browser-vhost удаляет этот маркер, а app-vhost удаляет входящие `X-Kunini-Auth-*`, поэтому подмена заголовков извне не превращается в SSO. Некорректные или частичные identity-заголовки отклоняются. Публичный порт Jellyfin по-прежнему не открывается.

Медиатека не копируется и не подключается через WebDAV. Каталог `/mnt/data/plex` передаётся контейнеру только для чтения как `/media`; создаются библиотеки:

- `Movies` → `/media/movies`;
- `Series` → `/media/series`;
- `Videos` → `/media/videos`.

Конфигурация и база находятся в `/var/apps/jellyfin/config`, а кэш и транскодирование — в `/mnt/data/.jellyfin-cache`. Для AMD APU включён VA-API через `/dev/dri/renderD128`.

Для получения метаданных и постеров Jellyfin использует закреплённые DNS-резолверы Quad9 (`9.9.9.9` и `149.112.112.112`). Это изолирует контейнер от системного DNS, который в текущей сети подменяет адреса TMDb на loopback.

## Развёртывание

```bash
./deployment/kunini/deploy.sh
ssh dekunin@192.168.28.3 /var/apps/jellyfin/deployment/initialize.sh
ssh dekunin@192.168.28.3 /var/apps/jellyfin/deployment/setup-nginx.sh
ssh dekunin@192.168.28.3 /var/apps/jellyfin/deployment/verify.sh
```

Пароль администратора `dkunin` создаётся один раз и хранится с правами `0600` в `/var/apps/jellyfin/secrets/admin-password`. Не добавляйте его в Git или журналы.

В приложении добавьте сервер `https://media-app.kunini.ru` и войдите локальной учётной записью Jellyfin либо через Quick Connect. Для повседневного просмотра рекомендуется отдельный локальный пользователь без прав администратора. Пользователи вида `kunini-<username>-<stable-id>` не имеют локального пароля, но могут авторизовать клиент через Quick Connect из уже открытого веб-интерфейса.

`deploy.sh` воспроизводимо собирает оба плагина в закреплённом .NET SDK-контейнере, выполняет C#- и JavaScript-тесты, монтирует DLL в Jellyfin только для чтения, оставляя служебные `meta.json` доступными Jellyfin для записи, и применяет TLS-конфигурацию только при наличии сертификата. До первого выпуска сертификата `media-app.kunini.ru` остаётся закрыт bootstrap-конфигурацией. `setup-nginx.sh` выпускает и проверяет отдельные сертификаты обоих доменов, после чего включает прямой клиентский вход.

## Обновление и откат

Перед обновлением измените tag и digest образа в `compose.yaml`, затем снова запустите `deploy.sh`. Если контейнер уже существует, его образ получает локальный тег `jellyfin/rollback:<UTC>`; последний тег записывается в `/var/apps/jellyfin/last-rollback-image`.

Для закрытия только прямого входа примените `nginx/media-app.kunini.ru.bootstrap.conf` как `/home/dekunin/nginx-sites/media-app.kunini.ru.conf` через `codex-nginx-apply`. Для отката только рекомендаций удалите mount `/config/plugins/KuniniDiscover` из `compose.yaml` и подключения `/KuniniDiscover/styles.css` и `/KuniniDiscover/script.js` из `sub_filter`. Для полного отката удалите также переменные `KUNINI_AUTH_*` и mount `/config/plugins/KuniniAuth`, восстановите предыдущий Nginx-конфиг без `sub_filter`, укажите сохранённый образ и выполните `docker compose -p jellyfin -f /var/apps/jellyfin/deployment/compose.yaml up -d`. Локальная учётная запись администратора остаётся пригодной для входа. Конфигурацию `/var/apps/jellyfin/config` перед обновлением следует архивировать отдельно.

## Проверка

`verify.sh` проверяет точный digest образа, здоровье контейнера, loopback-only порт, read-only медиатеку и оба плагина, DNS и HTTPS-доступность API/изображений TMDb, fail-closed поведение заголовков, регистрацию auth provider, API рекомендаций, три пути библиотек и состояние сканирования. Для `media.kunini.ru` проверяется анонимный редирект на Kunini Auth; для `media-app.kunini.ru` — сертификат, публичное обнаружение, реальный вход локальным Jellyfin-паролем, доступ с выданным token и публикация правильного адреса сервера. Полноценный браузерный SSO и визуальная полка рекомендаций проверяются отдельно с действующей Kunini-сессией.
